## 1. API Endpoints Audit

### 1.1 Authentication & Authorization

**Endpoint:** `POST /api/v1/auth/login`
- **Status:** ❌ **BROKEN**
- **Issue:** Password verification fails with default credentials (`admin@meridian.local` / `admin`)
- **Root Cause:** Password hash mismatch or invalid default password
- **Impact:** Users cannot login via standard credentials
- **Evidence:**
  ```bash
  curl -X POST "http://localhost:3000/api/v1/auth/login" \
    -H "Content-Type: application/json" \
    -d '{"email":"admin@meridian.local","password":"admin"}'
  
  Response: {"detail":"Invalid credentials"}
  ```
- **Recommendation:** 
  - Document correct default password or generate one during init
  - Implement password reset endpoint
  - Add "forgot password" flow

**Endpoint:** `GET /api/v1/auth/me`
- **Status:** ⚠️ **MISSING**
- **Issue:** No endpoint to get current authenticated user info
- **Impact:** Frontend cannot display current user
- **Recommendation:** Implement user profile endpoint

## 9. Performance Issues

### 9.1 Query Performance

**Issues Found:**
1. ❌ **N+1 Problem** - Findings query loads master records per finding
   - **Impact:** 100 findings = 101 queries
   - **Fix:** Implement eager loading / JOIN

2. ⚠️ **Missing Indexes**
   - Slow queries on `findings(module, status, tenant_id)`
   - Slow queries on `versions(created_at)`
   - Add indexes for O(log N) lookups

3. ⚠️ **No Query Pagination** - Endpoints return all results (memory/network waste)
   - **Fix:** Implement cursor-based pagination

### 9.2 Cache Usage

**Current:** Minimal caching
- ⚠️ Health endpoint not cached (runs every request)
- ⚠️ Analytics recomputed on every request
- ⚠️ Configuration data fetched fresh per request
- **Fix:** Add Redis caching with TTL

### 9.3 Worker Performance

**Issues:**
- ⚠️ Polars engine not enabled by default
- ⚠️ No batch processing (one record at a time)
- ⚠️ No async extraction (sequential)
- **Fix:** Implement concurrent extraction with connection pooling
