# Testing guide

How to run Meridian's tests locally and what CI runs. This replaces the root `TESTING_GUIDE.md` (a manual
playbook for an earlier round of go-live fixes, written against interfaces that have since changed). The
measured inventory, coverage and gaps are in [diligence/quality.md](diligence/quality.md); this page is the
how-to.

## Python

Python 3.12, from the repository root with `PYTHONPATH=$PWD` and the locked dependencies
(`pip install -r requirements.lock`).

```bash
pytest tests/ -q                       # the whole suite; Postgres tests skip without a database
pytest tests/ --collect-only -q        # what would run
pytest -m perf -s tests/checks/test_perf_400k.py   # opt-in performance tests (deselected by default, pytest.ini)
```

Tests named `*_pg.py` and the RLS suites need a throwaway Postgres 16 they may migrate:

```bash
export MERIDIAN_TEST_DB_URL=postgresql://user@host/throwaway_db
pytest -q tests/test_rls_conformance.py tests/test_rls_integration.py
```

Rule content has its own gates, also run in CI:

```bash
python -m checks.rule_reconciler --strict        # every rule reconciles with the SAP field dictionary
python scripts/generate_ddic_rules.py --check     # generated rules are current
```

Synthetic SAP extracts for tests and manual runs come from `tests/fixtures/synthetic_sap_data.py` and
`tests/fixtures/realistic_sap_data.py` (deterministic, seeded; no customer data). `scripts/e2e-seed-data.py`
writes them as CSV for `POST /api/v1/upload`. The configuration-matching datasets used by
`scripts/evaluate_config_matching.py` live in `tests/fixtures/config_matching/` and are regenerated by
`scripts/generate_config_test_data.py` (both scripts still name the old `Test Files/config_matching` path
until their owner updates `BASE_DIR`).

## Frontend

From `frontend/`, after `npm ci`:

```bash
npx tsc --noEmit                  # TypeScript strict
npm run lint                      # ESLint, zero warnings
npm run lint:tokens               # no raw colours, gradients, blur, ad hoc shadows or motion literals
node scripts/i18n-extract.mjs     # English, German and Japanese: 0 untranslated, 0 missing, 0 gaps
npm run check:contrast            # colour contrast arithmetic
npx vitest run                    # unit and component tests (add --coverage for the coverage floors)
npm run build && npx playwright test   # end-to-end, Chromium, against the production build
```

The Playwright specs run in fixture mode (`?fixture=1`) with the API stubbed: they test the screens, not
the engine behind them (see DR-1 in [diligence/roadmap-and-debt.md](diligence/roadmap-and-debt.md)).

## A live stack

To test the product end to end, bring up the development stack, migrate, and upload synthetic extracts:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
docker compose exec api alembic upgrade head
python scripts/e2e-seed-data.py --rows 5000 --out seed
```

Then upload the CSVs (attached to a registered system) and walk the screens without `?fixture=1`. The full
walk is described in [diligence/demo-script.md](diligence/demo-script.md), "Live demo".

Two resilience behaviours worth checking by hand on a live stack, both still as the old playbook described:

- **Model circuit breaker** (`llm/provider.py`): after 5 consecutive failed model calls the breaker opens
  for 60 seconds and calls fail fast instead of waiting for the timeout. Stop the model provider, make six
  calls that need it, and the sixth returns at once.
- **Licence worker outage** (`api/middleware/licence.py`, `is_cloudflare_unreachable`): licence-gated
  requests keep working for 2 hours after the licence worker first becomes unreachable, then answer 403
  (see [diligence/operations.md](diligence/operations.md), section 8).
