# v0.0.660

Previous release with notes: v0.0.659.

## Summary

Batch A of the app-like redesign adds the backend contracts the new screens need. All changes are additive: no existing endpoint changed its response shape.

## Features

- Cycle state per object on the objects summary: number, step (pull, clean, upload, score, compare), start time, parent run, and when and by whom the cleaning workbook was downloaded.
- Compare sets: new, resolved, regressed and persisting findings between two runs, each with a reason (data, new rule, rule removed, rule changed, records added, records removed). A multi-run compare accepts 2 to 10 runs.
- One paging and sorting contract (limit, offset, sort, total, next offset) on run lists, finding lists, a new portfolio list and a new monitor feed of new and regressed issues across objects. A bulk start endpoint starts 1 to 200 objects at once.
- Multi-file upload round trip: up to 20 corrected workbooks in one call, each linked to its parent run, with per-file success or error.
- Load history per object and a load order endpoint that reuses the existing load plan sequence.
- Cleaning workbook: a Start here sheet, an Allowed values sheet, an Examples sheet, a Needs owner status, and locked key columns with only the fix columns editable.

## Fixes

- The SAP round trip read the field label together with the field name; it now uses the name only.

## Known limits

- Classification of new, resolved and regressed is at record level, not field level.
- Paging is offset based; there is no cursor yet.
- The Load step of the cycle is not tracked on the server.
- The portfolio readiness figure uses default thresholds.
- Status, Owner and Comment columns in the workbook are still ignored on upload.
