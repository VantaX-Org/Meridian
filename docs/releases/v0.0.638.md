# v0.0.638

## Fixed

- The issue lifecycle no longer stalls on rules that hit the failing-record cap. Such rules list only part of their failing records, so they never auto-resolve issues. The resolve step now picks the rules that ran cleanly and listed every failing record first, and skips the step when a batch holds none. Before this, a batch made only of capped rules still scanned every open issue of those rules, which held a run's checks for over an hour.
- The per-batch table of present records is analysed after it is loaded, so the planner sees its real size.
