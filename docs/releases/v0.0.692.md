# v0.0.692

Status: not yet tagged. This note covers ops batch F and G: a stale browser tab now reloads once after a deploy, and the person who starts a download, an analysis or a migration run is told in-app when it finishes or fails. Change the heading if the number differs.

Previous release with notes: v0.0.691.

## Summary

After a deploy, a tab left open still asked for the old build's script chunks, which no longer exist, and landed on the error page. The global error page now spots that error and reloads the tab once, so it picks up the new build. Runs also finished silently unless someone was watching the jobs tray; the person who started one now gets a notification.

The two scheduler items in this batch (commit `next_run_at` before dispatch, skip a profile whose system already has a sync running) were already fixed on main by #723 and #735, so this release changes nothing there.

## Features

- Run notifications: when an extraction or analysis job finishes or fails, the user who started it gets an in-app notification (type `run`) that links to the run. A migration run notifies the user who requested it. A job that finishes twice, or was cancelled, notifies no one. Scheduled syncs have no starting user and stay silent, as before.

## Fixes

- Stale frontend after a deploy: a `ChunkLoadError` or a failed dynamic import caught by the global error boundary reloads the page once. A second such error within a minute shows the error page instead of reloading again, and without `sessionStorage` the page never reloads.
