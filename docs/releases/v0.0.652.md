# v0.0.652

Previous release with notes: v0.0.640, which covers the changes tagged v0.0.641 to v0.0.649. This note covers v0.0.650 to v0.0.652.

## Summary

This release completes the licence key rotation. The licence worker can rotate its JWT secret without logging users out. The API ships the new vendor Ed25519 public key. Legacy licence signatures are now refused unless an installation opts in.

## Features

- The licence worker accepts `JWT_SECRET_PREVIOUS` during a rotation. Tokens signed with either secret verify. New tokens are always signed with `JWT_SECRET`. (#646)
- The new vendor Ed25519 public key is first in `VENDOR_LICENCE_PUBLIC_KEYS` in `api/middleware/licence_keys.py`. The two older keys stay, so existing licences keep verifying. (#664)
- At startup, the API logs an error that names any legacy licence it finds while legacy signatures are off, and says how to opt in. (#652)

## Fixes

- The licence worker deploy runbook describes the overlap window. (#646)
- The administrator training guide, the access and security operations page and the known issues list describe the new default for legacy signatures. (#652)

## Database migrations

- None. The alembic head stays at 149.

## Configuration changes

- `MERIDIAN_LICENCE_ALLOW_LEGACY_SIGNATURES` now defaults to false. With it off, Meridian accepts only licences signed with the vendor Ed25519 keys built into the image. Set it to true only for an installation that still holds an old licence. Remove it once Meridian HQ issues that installation an Ed25519 licence. (#652)
- The licence worker reads `JWT_SECRET_PREVIOUS` during a JWT secret rotation. Remove it once the overlap window ends. (#646)
- The licence worker signs with `LICENCE_SIGNING_KEY_ED25519`. The vendor sets this secret in the worker. It never goes into the repository or an installation. (#664)

## Deployment

1. Deploy the licence worker with the new signing key, then confirm an online licence response carries an Ed25519 signature.
2. Run the standard update in [docs/meridian-update-guide.md](../meridian-update-guide.md) while no extraction or analysis is running.
3. Check that the startup log has no legacy licence error.

## Verification

- An online licence check returns valid with legacy signatures off.
- `/health` returns 200 and all containers report healthy.

## Rollback

- Run `scripts/update.sh --rollback`. The release has no migrations, so no database step is needed.
- If only the licence check fails, set `MERIDIAN_LICENCE_ALLOW_LEGACY_SIGNATURES=true` and restart the API while the licence owner issues a new licence.

## Known issues

- The two older vendor public keys are still in `VENDOR_LICENCE_PUBLIC_KEYS`. A later release removes them once no installation depends on them. Owner: the platform engineering lead.
