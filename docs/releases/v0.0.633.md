## Summary

This release runs Meridian's own Aletheia engine beside the platform. SuccessFactors migration workbooks now learn their columns and report columns the source system does not return. Every table uses one spec. Old pre-update backups are pruned. The guides, training and tour videos are brought in line with the screens. Dependabot is removed.

## Features

- **Meridian's own Aletheia engine** (commit b1a924cfa). A new `aletheia` service runs under the compose profile `aletheia` with the volume `aletheia_data`. The API reaches it at `ALETHEIA_URL`. The client sends only aggregate metrics: composite, failing_rules, affected_records, critical, high, blockers and auto_fixable_pct. New routes are `/api/v1/aletheia/engine` and `/api/v1/insights/engine-drivers`. A new Administration screen shows the engine.
- **Self-learning SuccessFactors workbooks** (commit 8bd66187d). When a target workbook carries a column that the extraction does not yet fetch, Meridian records it and adds it to the next extraction. Each learned property is checked against the tenant's own metadata. The Migration screen lists the learned columns.
- **Update the run** (commit 8bd66187d). People who can start extractions get an "Update the run" button on the Migration screen. It starts a fresh extraction of the same modules.
- **Columns the source does not return** (commit 9ec6f0b23). The workbook check reads the last run's coverage. A column whose field came back unavailable is reported as not in the system, with a notice on the Migration screen.
- **Learned columns kept** (commit c03e84505). The Migration note says the workbook check keeps learned columns, in English, German and Japanese.
- **Backup retention** (commit f143476e0). `scripts/update.sh` keeps only the newest five `backups/pre-update-*.dump` files. `BACKUP_KEEP` changes the number. Other dumps are not touched.

## Configuration changes

New environment variable names. Values are set on the host in `docker/.env` and are never in the repository.

| Name | Read by | Note |
|---|---|---|
| ALETHEIA_URL | api | Engine address. The compose file sets a default. |
| ALETHEIA_TOKEN | api and the aletheia service | Shared token for the engine |
| ALETHEIA_TENANT | api | Tenant name sent to the engine. The default is "meridian". |
| ALETHEIA_LICENSE_KEY | aletheia service | Engine licence. Without it the engine runs unlicensed. |
| ALETHEIA_DEPLOYMENT_ID | aletheia service | The default is "meridian". |
| ALETHEIA_LICENSE_SERVER | aletheia service | Licence server for the engine |
| MERIDIAN_ALETHEIA_IMAGE | compose | Engine image. The default is cortex0 1.7.0. |
| BACKUP_KEEP | scripts/update.sh | Number of pre-update dumps kept. The default is 5. |

Other changes:

- `docker/docker-compose.customer.yml` adds the service `aletheia`, the profile `aletheia` and the volume `aletheia_data`.
- `.github/dependabot.yml` is deleted. Dependency pins now need a manual refresh.

## Deployment

Follow [docs/meridian-update-guide.md](../meridian-update-guide.md). For the customer deployment, follow [docs/project/cutover-and-go-live-plan.md](../project/cutover-and-go-live-plan.md).

```bash
sudo bash scripts/update.sh --version 0.0.633
```

- Stop extractions and runs first. The script refuses to run while one is going.
- The host needs 10 GB of free disk.
- The script now also pulls the engine image and starts the `aletheia` service. A failure there gives a warning and does not stop the update.
- To run the engine licensed, a person with sudo on the server appends ALETHEIA_DEPLOYMENT_ID, ALETHEIA_LICENSE_KEY, ALETHEIA_TOKEN and MERIDIAN_ALETHEIA_IMAGE to `docker/.env`. Then run the update again for the running version.

## Rollback

```bash
sudo bash scripts/update.sh --rollback
```

This returns to v0.0.632. This release has no migrations, so no database restore is expected. A rollback does not undo database changes. If a restore is needed, use the pre-update dump named in the script output. The `aletheia` service and its volume are not used by v0.0.632.
