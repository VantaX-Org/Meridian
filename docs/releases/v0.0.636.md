## Summary

This release adds a cleaning workbook for each object. The workbook is an Excel file that lists every failing record and field from a run, with the current value, a suggested value where Meridian has one, the rule that failed, why it failed, its severity and the steps to fix it. The data owner works through it, records the corrected value and marks each row done.

## Features

- **Cleaning workbook per object.** `GET /api/v1/reports/{version_id}/cleaning/{module}.xlsx` returns the workbook for one module of a run. It works for every catalogue module, not only SuccessFactors. The report library and report schedules carry the new type `cleaning_workbook`, so a large module can be built by the worker and downloaded from the report history.
- **Four sheets.** "How to use" explains the columns and the workflow. "Summary" lists each rule with its severity, failing count and pass rate. "Instructions" gives the numbered fix steps for each rule and the automatic fix, if the rule has one. "Records to clean" holds one row per failing record and field, sorted by severity, with a Status drop-down (Open, In progress, Done, Not an error) and an empty column for the corrected value.
- **Suggested values are never invented.** A suggestion comes from one of three places, and the Source column names it: a fix proposed in the run ("Run proposal"), the rule's automatic fix applied to the current value ("Rule auto-fix"), or the rule's value map ("Value suggestion"). Where none applies, the suggestion is blank.
- **Large modules split.** More than 100,000 rows continue on "Records to clean 2", "Records to clean 3" and so on, below the Excel row limit.

## Checked on real data

The workbooks were built on the production server for the latest SuccessFactors run, and the customer's two migration workbooks were filled from the same run. Only counts are recorded here. The files stay on the server.

| Module | Workbook size |
|---|---|
| Succession planning | 18 KB |
| Benefits | 100 KB |
| Performance and goals | 295 KB |
| Payroll integration | 430 KB |
| Compensation | 858 KB |
| Employee Central | 7.3 MB, about 7 minutes |
| Recruiting and onboarding | See below |

| Migration workbook | Sheets | Sheets filled | Columns matched | Mandatory columns unmatched | Rows ready | Rows held |
|---|---|---|---|---|---|---|
| Employee | 21 | 18 | 135 of 544 | 3 | 25,613 | 54,573 |
| Foundation | 42 | 17 | 31 of 798 | 39 | 34,117 | 3,214 |

The column match on real data is lower than the check in v0.0.635. That check used test data with a value in every field. The run has no data for many workbook columns, so those columns stay empty. Rows are held when a mandatory value is missing, a value is not in the workbook's picklist, or a value is longer than the column allows. The fill wrote a new workbook rather than the customer's own layout for both files (RAID I-07).

Employee Central and Recruiting and onboarding are the two largest modules. Building their workbooks takes several minutes, so build them on the worker: add a report schedule of type "Cleaning workbook" for the module, press Run now and download the file from the report history. The direct link times out after ten minutes.
