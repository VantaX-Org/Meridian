# v0.0.672

Status: not yet tagged. v0.0.671 is the latest tag, and the next number is expected to be v0.0.672. This note covers the changes on main after the v0.0.671 note was written: the shell from Batch E (#691), which is inside the v0.0.671 tag but is not described in its note, and the Load screen (#692), which is not yet in any tag. Change the heading if the number differs.

Previous release with notes: v0.0.671.

## Summary

Batch E of the app-like redesign adds the new shell and the Load screen. Both stay opt-in under "Try the new Meridian", so people who have not turned it on see no change.

## Features

- Shell (#691, in the v0.0.671 tag): a rail on wide screens and a bottom bar on phones, with a top bar and a command palette. The rail order follows the person's role. Business roles see Portfolio, Objects, Work and Monitor, with Load added when they can export. Stewards lead with Work, leads with Load, and admin and Basis roles with More and without Load.
- Work, Monitor and More screens (#691): Work and Monitor are new destinations. More groups the remaining functions so none is lost, and opens the existing screens inside the new shell.
- Redirects (#691): addresses from the old interface send people to the matching new destination when they have the new Meridian turned on.
- Load screen (#692): the Prepare tab walks through three steps: choose the target, validate, then load the files. A History tab lists earlier loads.
- Analysis, Compare, Plan, S4, Go-live and Waves tabs on the Load screen (#692): Analysis mounts the existing Migration screen unchanged. The other tabs open the existing screens with the context carried across.
- German and Japanese strings for the shell and the Load screen, alongside English.

## Fixes

- A duplicated translation key was removed, and the shell rail now uses the motion tokens instead of fixed timings (#691).

## Docs and training

- The journeys by role page was updated to match the new destinations.

## Database migrations

None. No file under `db/migrations/versions/` changed, so the alembic head is the same as in v0.0.671.

## Configuration changes

None. No environment variable was added, renamed or removed.

## Deployment

The changes are in the frontend only. Deploy the frontend image. No API or worker change is needed.

## Verification
