# v0.0.671

Previous release with notes: v0.0.662.

## Summary

Batch D of the app-like redesign adds the object page under /next/o/{system}/{module}. It is opt-in, like the rest of /next, and changes nothing for people who have not turned on "Try the new Meridian". The page is built around one object and the run it is on, with the cleaning cycle as the first tab.

## Features

- Object bar: breadcrumb back to Objects and the system, the object name with its code beside it, a run switcher, the run's DQS with its change from the run before, and the cycle position.
- Run switcher: pick any run of the object, newest first, with status, kind (scheduled, started by hand, cleaned), the run it was cleaned from, and the DQS. The chosen run is kept in the address, so a copied link opens the same run, and is remembered for the object in the browser tab.
- Cycle tab with five steps: pull from the system, download and clean the workbook, upload the cleaned workbook, score, and compare with the run before. The compare step lists new, resolved and regressed findings with the reason for each in words and its code beside it, plus the field values before and after.
- Source, projected target and actual target DQS side by side where a paired source and target run exist, with the reasons they differ.
- Runs tab: pages through every run of the object fifty at a time, filters by status, kind and date, nests cleaned runs under the run they came from (or shows them flat), exports the page as CSV, and compares any two runs picked from the list.
- A tab registry for the object page, so the existing object screens (overview, rules, records, fixes, trend, readiness and the rest) open as tabs with the run carried across. On a phone the tabs that do not fit move into a More list.
- The compare records list on the server now also returns values_before and values_after (the record's field values in each run). These fields are additive; no existing field changed.

## Fixes

- The selected segment of a segmented control and the accent chip now meet 4.5:1 contrast in light and dark when the page sits inside the current shell.

## Known limits

- The route stays under /next/o until the cutover in Batch E, and the current shell is still nested inside the new one.
- Workbook scope and per-owner workbooks are not offered by the server yet, so they show as disabled.
- The upload step does not check the workbook's row count before it sends.
- The before value is empty for new and regressed findings when the record did not fail in the earlier run.
- Kind and date filters on the Runs tab run in the browser over the loaded page.
- Duration and record counts come from the run timeline and show a dash when the timeline has none.
