# v0.0.639

## Fixed

- SuccessFactors target workbooks now fill every column the tenant can supply, not only the external codes. Workbook column ids in kebab case or with spaces (`person-id-external`, `job code`) are read as OData property names. Each column is resolved against the tenant's `$metadata`, allowing for spelling differences such as `effectiveStartDate` against `startDate`, `cust_` prefixes, localised names and navigation properties. The extract fetches every resolved column before the analysis runs.
- Country-specific sheets are filled. CSF Personal Info (Global Info), CSF Legal Entity and CSF Job Classification read every country entity set of their family (`PerGlobalInfo*`, `FOLegalEntityLocal*`, `FOJobClassLocal*`) and join the rows.

- Twenty-three SuccessFactors national ID rules compared the ID with the birth date through `strftime`, which raises on dates outside the range Python supports. The checks task stopped on such a record. The rules now build the date digits from the year, month and day, so an out-of-range date no longer stops the run.
- Logistics and address rules that the rule audit found wrong were corrected.

## Added

- 117 rules from a rule-by-rule audit of the ECC packs: HCM PA121 to PA142, production planning PP411 to PP419, plant maintenance PM370 to PM375, purchasing PUR420 to PUR428, quality management QM134 to QM140, project system PS166 to PS171, sales orders SDSO341 to SDSO352 and deliveries and billing DL090 to DL105. Each new rule has a test that proves it flags a bad record and passes a good one.
- The HCM extract reads the fields the new rules need, including PA0014 and PA0015 and the configuration tables T549A, T510A, T510, T512Z and TCURC.
- The check engine joins delivery headers to delivery items (LIKP to LIPS) and billing headers to billing items (VBRK to VBRP), so a rule can compare header and item fields.

- Three canonical SuccessFactors dictionary tables: PER_GLOBAL_INFO, FO_LEGAL_ENTITY_LOCAL and FO_JOB_CLASS_LOCAL.

## Notes

- Columns the tenant does not have stay empty and are reported as not in the system. Meridian never invents a field.
