## Summary

This release makes the SuccessFactors cleaning workbooks list every failing record that a run counted, where the source data allows it, and says plainly when a workbook holds fewer rows than the rule counted.

## Fixes

- **Record keys use the SuccessFactors unique ID.** Three tables were keyed on fields that are not unique in SuccessFactors, so records that shared the key were stored as one row and dropped from the cleaning workbook. The keys now end with the real SuccessFactors ID: job applications add `APPLICATION_ID` (JobApplication.applicationId), performance review results add `FORM_DATA_ID` (FormHeader.formDataId), and onboarding candidates add `PROCESS_ID` (ONB2Process.processId). All three fields were already in the dictionary and in the extract.
- **Listing note on the Summary sheet.** A new "Listing note" column says how many failing records are not in the file when the stored rows are fewer than the count. The run stores at most 100,000 records per rule. The cap stays, to protect worker memory, and the note tells the data owner to fix the listed rows and rerun to see the rest.

## Found on the first clean SuccessFactors run

The old SuccessFactors runs were deleted and the extract was run again as version 1 with the current column set. Comparing counted and stored records per rule found the key collisions fixed above, two rules on job applications above the 100,000 cap, and two extraction gaps that keys cannot fix. The gaps are logged as RAID issue I-08.

## Upgrade

No migration. Rerun checks on the SuccessFactors run after the upgrade so the new keys apply.
