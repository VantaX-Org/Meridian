## Summary

This release closes the open engineering items from the v0.0.633 sustain pack. ECC and S/4HANA target workbooks now learn their columns from the SAP data dictionary. Two cosmetic table faults are fixed. The documentation and script faults listed in the known issues are corrected.

## Features

- **DD03L learning for ECC and S/4HANA workbooks** (commit 498fe9fd9). When an uploaded target workbook has a column the dictionary does not know, Meridian looks the field up in DD03L on the source system. Only ABAP systems are asked (ECC, S/4HANA on-premise, EWM). Only the tables the run's objects use are searched. The read selects TABNAME and FIELDNAME with a filtered WHERE clause, in chunks of 40 tables by 40 fields, so it never scans DD03L.
  - A field held by one table is learned and requested by the next extraction.
  - A field held by several tables is not guessed. The Migration screen lists it under "Columns on more than one table" with the candidate tables. The user writes TABLE-FIELD in the workbook header.
  - A field held by no table is reported as not in the system.
  - If the system cannot be read, a warning is logged and the export goes on without SAP learning (commit abd2efde9).
  - Lookups are cached per system in the API process. A field added in SE11 is seen after the next restart or update.

## Fixes

- The Fix grid "Object and run" column lines up, and the Monitors "Usual range" text no longer wraps (commit 8e22b5d1f). The administrator training screenshot of the Monitors screen and its PDF are refreshed.
- `docs/troubleshooting.md` uses the customer compose files, the `ollama` service, the `meridian` database user, the current licence settings and the nginx health address (commit 4058e84ad).
- `scripts/healthcheck.sh` checks `/health` through nginx and accepts the current status format.
- Every Prometheus alert carries a `runbook_url` that points to the alert table in `docs/sustain/monitoring-and-alerting.md`.
- `scripts/manage_users.py` reads the deployment tenant from `MERIDIAN_TENANT_ID` or `DEPLOYMENT_TENANT_ID`, and sets it with a bound parameter.

## Still open

These items need a person outside engineering. They are tracked in the [known issues](../sustain/known-issues.md) and the [RAID log](../project/raid-log.md).

- The Aletheia engine settings must be appended to the server env file by a person with sudo.
- The engine image pin (1.7.0 or 1.8.0) is an owner decision.
- The draft grant for the embedded engine waits for the licensor's sign-off.
- SuccessFactors mandatory columns that the source does not return need the real field names.
- Load-tool validation needs a real import template.
- Licence narrowing waits for the customer's go-ahead.
- The signed-in go-live acceptance run needs a human tester.
