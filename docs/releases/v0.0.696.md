# v0.0.696

This note covers the open items left by the app-like design spec and the clean-cycle audit: one ZIP for many cleaning workbooks, an "Add to load" bulk action, an "Open Upload" link in the download toast, and the score change per run on Monitor. Change the heading if the number differs.

Previous release with notes: v0.0.694.

## Summary

Downloading workbooks for many objects used to start one browser download per run. The portfolio and the home feed now ask for a single ZIP. After the download, the success toast stays for twelve seconds and offers "Open Upload" so the user can go straight to the next step of the cycle. A selection can be sent to Load with "Add to load", which opens load prepare with those objects ticked. Each run on Monitor now shows its DQS and the change since the run before.

## Features

- `GET /api/v1/reports/cleaning.zip?runs=<version>:<module>,...` returns one ZIP holding the cleaning workbook of each listed run, up to 50 per request. It needs the `export` permission and a licence for every module asked for (402 otherwise). A bad pair or more than 50 pairs is refused with 422, and a run that does not exist with 404. Each workbook is audited as its own export, so the cycle step "downloaded" is set for every run in the ZIP. Two runs of the same object get distinct file names.
- Portfolio and home feed: "Download workbooks" uses the ZIP for more than one run and the single workbook for one. A bigger selection is split into ZIPs of 50.
- The download toast carries an "Open Upload" action that opens the upload panel for the same runs. Toasts can now carry one action button.
- Bulk bar: "Add to load" links to `/load?objs=<modules>`, which ticks the selected objects on the newest load run.
- Monitor: each run line shows "DQS 80.0 (+5.0)", read from the portfolio's current and previous score.

## Fixes

- The "Prepare load files" link on a feed card passed `object=` and a scoring run id, which load prepare ignores. It now passes `objs=` so the object is ticked.
