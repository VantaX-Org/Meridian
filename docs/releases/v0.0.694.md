# v0.0.694

Status: not yet tagged. This note covers the last open gaps from the clean-cycle and load-format audit: an edited workbook can now go back onto a run that came from a file upload, and the full build-to-apply round trip on material master is under test. Change the heading if the number differs.

Previous release with notes: v0.0.691.

## Summary

The audit listed eleven gaps in the pull, clean in Excel, upload, re-score cycle. Ten were already closed on main by earlier batches. The one still open was that a run created from a file upload could not take an edited file back: the upload route refused any run whose data was not an extraction bundle. This release lifts that limit. It also adds a test that builds a real cleaning workbook for a synthetic MARA sample, reads it back, and applies the corrected value, so the cycle that was once broken on material master cannot break again unnoticed.

## Features

- Upload back onto a file-upload run: `POST /upload/roundtrip` now accepts a parent run whose data is a single flat parquet file with TABLE.FIELD columns. The edits are written into a copy of that file, stored as `staging/<tenant>/<version>.parquet`, and the checks run on the copy as they do for any upload. Records are matched on the table's key fields, as for an extraction. A parent with no stored data is still refused, now with the message "This run has no stored data to edit."

## Verification

- `tests/test_sf_roundtrip.py`: a new test builds the cleaning workbook for a synthetic MARA sample, reads it back with `read_upload`, fills one corrected value, and checks that `cleaning_edits` and `apply_edits` land exactly one edit on the bundle. A second new test edits a flat upload file, checks that a dry run writes nothing, that the copy carries the edit and every other column, and that the parent stays unchanged.
- `tests/test_upload_roundtrip_route.py`: a run from a file upload now takes the edited file and its copy is one parquet object; a run with no stored data is refused.
- To confirm (release owner): upload a small material file, download its cleaning workbook, fill one corrected value and upload it back. A "(cleaned)" run should appear and re-score.

## Known issues

- A flat upload holds several tables in one frame. When a key appears on more than one row (for example one material with several plants), an edit to a header field is written to every row with that key, which is the same value the header table holds.
