# v0.0.712

Status: not yet tagged. This note covers the instance move to a new SuccessFactors tenant (PRs #762, #765, #769) and migration 186. Change the heading if the number differs.

Previous release with notes: v0.0.697.

## Summary

Meridian can now move a licensed object from one SuccessFactors tenant to another. The records keep their IDs, every rule fix is applied to the values on the way, and the full history comes across with the current records. Records that the rules cannot fix still load as they are and go on the needs-review list. A pilot mode moves a small sample first: 10 people per country, pay band and status, plus their managers. Countries can be excluded from a plan; excluded people are counted and never loaded.

## Features

- Instance move: plan, preflight, dry run against the target, load and validation, with a per-record status and a cleansing log for every changed value.
- History extract for SuccessFactors: every effective-dated entity set and picklist is read, not only the current rows.
- Pilot sample: `sample.per_cell` on a plan picks the sample. Missing managers are added so that the reporting lines resolve.
- Excluded countries: `exclude_countries` on a plan. The Scope step shows the excluded countries as chips.
- Country picklists are bound per row, and near-miss picklist values snap to the target code (#762).

## Fixes

- SuccessFactors lockout guard: an extract stops at the first authentication failure instead of retrying, so a wrong password cannot lock the API user.
- Migration 186 adds `move_plans.sample` and `move_plans.exclude_countries` to databases that ran the first version of 185.
