Methodology

Every figure in this report is computed by deterministic checks over the extracted records. No language model is involved in any score, count or ranking.

Score

Each check yields a record-level pass rate. A dimension score is the check-weighted average of those pass rates, with each check weighted by its severity. A module score is the weighted mean of its dimension scores. The data quality score (DQS) is the weighted mean of the module scores.

Critical cap

Failing critical checks cap a module score: one failure caps it at 85, two or more at 70, once the failures exceed the tenant's tolerance for the module.

Impact

Rule impact is the number of failing records multiplied by a severity weight: {% for sev, w in methodology.impact_weights.items() %}{{ sev }} {{ w }}{% if not loop.last %}, {% endif %}{% endfor %}. A root cause cluster adds up the impact of the rules that fail on the same field. Impact ranks work. It is not a currency value. Priced value at risk is shown per business process (L1) and is never added across processes.

Sources

Findings, scores and run history come from the analysis runs stored in this installation. Migration readiness uses the S/4HANA readiness rule map shipped with the product. Cleansing counts come from the proposed, approved and applied corrections recorded against the run. Times are South African Standard Time.
